## 5. Decisions taken with the feature owner

1. **R-01, R-02, R-03 → Fix now.** All three hand back to `implement`. R-03 additionally wires a
   typecheck gate so the class cannot recur silently, and sets
   `invalidWhereValuesBehavior: { undefined: 'throw' }` on the DataSource.
2. **T49(b), AC-36a → widen the test.** Confirmed by execution: the test passes **3 runs of 3 in
   isolation** and fails only inside the full suite. AC-36a (`spec.md:464-468`) promises the transfer
   is denied and exactly one Manager is preserved — it mandates no status code. Both `[200,409]` and
   `[200,403]` are documented for the route and both preserve one Manager; which one appears depends
   on whether the loser's guard read lands before or after the winner commits. The test will assert
   exactly one `200`, the loser in `{403, 409}` with its matching code, exactly one
   `warehouse_manager` row, and that the winner's `formerManagerRoleId` was applied. The load-bearing
   invariant assertion already exists at `:636-639`, so this removes a scheduler dependency rather
   than weakening a contract. **The contract does not change.** Raised separately: a lost race
   surfacing as 403 reads to the outgoing Manager as "you are not allowed" for something they were
   allowed to do a moment earlier — a UX wrinkle, not a contract violation.
3. **T49(a) → ratified.** The `access` contract defines `RoleUnavailable` for Role-target routes and
   `MemberOrRoleUnavailable` for member-or-Role routes; these two routes carry the Role as sole
   target, so the workspaces reference was a transcription slip. The re-shape was declared
   behaviour-preserving, no consumer keys on either string, and non-disclosure is identical. T49
   splits: (a) done with the decision recorded; (b) per decision 2. The process point in R-05 stands —
   a decision declared blocking was made in code before ratification.
4. **The stage-2/3/design backlog → registered as tasks (T63+),** with S2-06/R-04 first, since it is
   what allowed 46 tasks to be marked done over a red integration tier.

## 7. Gate result

**CHANGES REQUESTED.**

The remediation lane did real work: eleven of twelve integration failures are genuinely fixed, all
thirteen stage-1 findings except T49 are closed with non-tautological tests, S1-06 was fixed
_structurally_ rather than per-caller, and no realigned integration spec was weakened to match wrong
code. That last point was checked directly and matters — it is the failure mode a remediation lane is
most prone to.

Three things block ship:

- **R-01** — two 503s the lane itself made raisable reach the member as a generic toast, recreating
  the defect shape that made S1-03 stage-1.
- **R-02** — six owner-transfer assertions were deleted rather than moved, including the only
  coverage of an Owner lacking the reassign Permission.
- **T49(b)** — the integration tier is not green.

The deeper result is that **the first review's root cause is still open**. S2-06 was named as the
reason 46 tasks were marked done over a red tier, was accepted "Fix now", and is still unwired with
no CI in the repository. R-03 shows the same pattern a second time in a different gate: 42 type errors
invisible to every command the pipeline runs, one of which had already silently reverted a security
fix at its own test site. Until both gates are wired, a green local run is not evidence that this
feature works.

Re-run §2 in full — including the integration tier and `tsc --noEmit` — before the next verdict.
