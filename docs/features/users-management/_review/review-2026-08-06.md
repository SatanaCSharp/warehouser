### Stage 2/3 — quality, convention, architecture (deferred to a fast-follow)

Recorded here, not blocking this ship, at the user's direction:

- `AuthModule` was made `@Global()` specifically to dodge the `users/module-boundaries.spec.ts` import check — a service-locator pattern the system architecture doc explicitly prohibits. Revert; have `UsersModule` import `AuthModule` explicitly like `access/rest/rest.module.ts` does.
- `users` module skips the mandated `usecases/usecase.module.ts` / `rest/rest.module.ts` / `index.ts` barrel structure every other module (`access`, `auth`) follows.
- `module-boundaries.spec.ts` doesn't assert the "no framework imports in `users/domain`" rule it was written to enforce (currently compliant by luck, not by test).
- Error factories duplicated inline in four command files instead of living in `users/domain/errors/`.
- `data-model.md`'s deletion-sequencing §3 narrative is factually wrong about FK deferral semantics (the code's workaround is correct; the doc prose isn't).
- Three `users.*_unavailable` error codes / 503 responses are unreachable dead surface (no command wraps persistence failure in a `SystemError`) — precedent-consistent with an existing `access` gap, but contract was locked with these responses.
- `users-permissions.spec.ts` is tautological (asserts enum constants equal themselves; never reads the migration or OpenAPI).
- `AccessMemberRead.email` is `.optional()` in the shared contract but always populated by an `INNER JOIN` server-side — should be required.
- `updateEmail`/`updateCredential`'s `affected === 1` return value is discarded by both callers.
- Several unrecorded visible deviations from the approved design (avatar circles, mobile collapse treatment, field-description copy, password-reveal icon vs. text button).
- Role field uses a raw `<select>` instead of the design's HeroUI `Select`; its error isn't associated with the control via `aria-describedby`/`isInvalid`.
- Empty-Role submit on Create Member fails silently (RHF `required` message is empty, form has `noValidate`).
- Members section's `aria-label` landmark stays "Roles" even when viewing the Members tab.
- Success copy for email/password change omits the session-effect statement (sessions stay active vs. end) the design handoff requires.
- Focus isn't moved to the first invalid field after submission in any of the three dialogs.
- No colocated `DeleteMemberDialog.spec.tsx`; cache-invalidation test coverage only covers `createMember`, not the `CurrentAccess` refetch/stale-control-removal postcondition `sad.md` §6.5 describes.
